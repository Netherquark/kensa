\section{Problem Statement}

CERN's Large Hadron Collider (LHC) operates at a proton bunch-crossing frequency of 40\,MHz, corresponding to a bunch collision interval of $\Delta t = 25\,\text{ns}$. At design luminosity, proton-proton ($pp$) collisions occur at a center-of-mass energy $\sqrt{s} = 13\,\text{TeV}$, yielding $\mathcal{O}(10^9)$ inelastic proton-proton interactions per second. Experimental general-purpose detectors --- CMS and ATLAS --- generate raw sensory readouts at multi-terabit-per-second bandwidths ($\approx 40\,\text{TB/s}$). Because persistent storage and downstream processing bandwidth are bounded to $\mathcal{O}(1\,\text{kHz})$ write rates, hardware-level trigger systems (Level-1 / L1) must make zero-loss filtering decisions under an ultra-strict latency budget of $\mathcal{O}(1\,\mu\text{s})$ on custom FPGA architectures, followed by High-Level Trigger (HLT) software filter farms. 

To enable exploratory research into machine-learning-driven L1 trigger anomaly detection and unsupervised search for Beyond-the-Standard-Model (BSM) signatures without prior physics bias, benchmark datasets have been released to the research community. In particular, Govorkova et al.\ published an open-access training corpus on Zenodo (Record 5046428) representing simulated 40\,MHz trigger events as fixed-width, low-level reconstructed physics tensors packaged in HDF5 format~\cite{govorkova2022lhc}. The verified dataset file \texttt{background\_for\_training.h5} ($646.4\,\text{MB}$, MD5 \texttt{08cb4801229f9d480567f8d3f5cac134}) encapsulates $13{,}451{,}915$ collision events, each structured as a $(19 \times 4)$ floating-point tensor totaling $1.022\times 10^9$ scalar fields.

Processing this corpus at full depth presents a quintessential Big Data engineering and scientific computing challenge. Naive in-memory analytics fail due to the multi-gigabyte uncompressed memory footprint and the computational cost of per-particle parsing. Moreover, data corruption, coordinate wrapping errors, non-finite entries, and misidentified padding can silently bias downstream statistical inferences and machine learning models.

The primary engineering and analytical challenge of this study is to formulate and implement a \textbf{rigorous, bounded-memory, end-to-end Big Data pipeline} that:
\begin{enumerate}[label=(\alph*)]
    \item establishes cryptographic provenance and structural verification against Zenodo REST API endpoints without premature memory allocation;
    \item executes an exhaustive, non-sampled, chunk-wise data quality audit over all $1.022\times 10^9$ tensor scalars across six formal consistency criteria;
    \item implements bounded-memory columnar ETL transforming dense fixed-width tensors into typed, Snappy-compressed Apache Parquet with exact row-preservation guarantees ($N_{\text{out}} = N_{\text{in}} = 13{,}451{,}915$);
    \item executes distributed Spark SQL analytics covering multi-dimensional aggregations (\texttt{GROUP BY WITH ROLLUP}), windowed ranking (\texttt{DENSE\_RANK() OVER (PARTITION BY n\_jets)}), and 2D kinematic phase-space distributions;
    \item demonstrates core MapReduce paradigms via native Spark RDD key-value reductions alongside standalone Hadoop Streaming and Pig Latin dataflow compatibility layers;
    \item deploys an online, multi-pass unsupervised clustering workflow (\texttt{MiniBatchKMeans}, $K=8$) to rank topological Standard Model outliers in standardized kinematic feature space;
    \item and compiles all quantitative analytical outputs into traceable, reproducible, publication-grade visual analytics.
\end{enumerate}

\textbf{Scope Boundaries:} This project operates within a containerized single-host Docker runtime deploying Apache Spark in \texttt{local[6]} multithreaded mode. The input file is an offline simulation benchmark, not a live physical LHC stream, and the study makes no claims of sub-microsecond hardware latency or multi-node cluster deployment. Furthermore, the dataset is an unlabelled Standard Model background cocktail without per-event signal ground truth; consequently, supervised signal-detection metrics (such as ROC-AUC, sensitivity, or discovery significance) are neither defined nor claimed.

\section{Background and Physics Context}

\subsection{LHC Trigger Architecture and the 40\,MHz Challenge}

At the CERN Large Hadron Collider (LHC), colliding bunches of protons intersect every $25\,\text{ns}$ ($40\,\text{MHz}$) at a center-of-mass collision energy of $\sqrt{s} = 13\,\text{TeV}$. At design instantaneous luminosity ($\mathcal{L} \approx 2 \times 10^{34}\,\text{cm}^{-2}\text{s}^{-1}$), each bunch crossing generates an average of $\langle\mu\rangle \approx 20$ to $50$ overlapping inelastic proton-proton collisions, termed \emph{in-time pile-up}. Detecting rare new-physics processes amidst this overwhelming rate requires real-time data reduction of four orders of magnitude:
\begin{equation}
    \text{Raw Ingestion: } 40\,\text{MHz} \xrightarrow[\text{Hardware Trigger (L1)}]{\text{Latency } \le 3.8\,\mu\text{s}} \approx 100\,\text{kHz} \xrightarrow[\text{Software Farm (HLT)}]{\text{Latency } \approx 100\,\text{ms}} \approx 1\,\text{kHz} \text{ to Storage}.
\end{equation}

The Level-1 (L1) trigger executes on custom radiation-hardened ASICs and FPGAs directly mounted on detector backplanes. L1 decision algorithms must perform real-time object reconstruction --- identifying candidate electrons, muons, hadronic jets, and global missing energy --- and execute filtering decisions before on-detector ring buffers overflow. The 40\,MHz benchmark dataset released by Govorkova et al.\ represents an idealized emulation of this low-level reconstructed L1 trigger output stream~\cite{govorkova2022lhc}.

\subsection{Simulation Chain and Event Selection}

The dataset was generated using a standardized High-Energy Physics Monte Carlo simulation pipeline~\cite{govorkova2022lhc}:
\begin{itemize}
    \item \textbf{Hard Scattering and Parton Showering:} Generated with \texttt{PYTHIA 8.2} at $\sqrt{s} = 13\,\text{TeV}$, simulating leading-order matrix elements, initial- and final-state radiation (ISR/FSR), and hadronization using standard Tune 4C parameterizations.
    \item \textbf{Parametric Detector Simulation:} Processed via \texttt{DELPHES 3.4.2} configured with the CMS Phase-II detector card. Detector calorimeters and tracking systems are parametrically modeled. Pile-up is sampled from a Poisson distribution with mean $\langle\mu\rangle = 20$.
    \item \textbf{Pre-selection Filter (Single-Lepton Trigger Emulation):} Events are retained only if they satisfy standard single-isolated-lepton trigger criteria:
    \begin{equation}
        \text{Acceptance: } \left(N_{e}(p_T > 23\,\text{GeV}, |\eta| < 3.0) \ge 1\right) \quad\text{OR}\quad \left(N_{\mu}(p_T > 23\,\text{GeV}, |\eta| < 2.1) \ge 1\right).
    \end{equation}
    \item \textbf{Object Inclusion Thresholds:} Once an event satisfies the trigger, reconstructed objects are recorded up to fixed capacity limits:
    \begin{itemize}
        \item Up to 4 electrons with $p_T > 3\,\text{GeV}$ and $|\eta| < 3.0$.
        \item Up to 4 muons with $p_T > 3\,\text{GeV}$ and $|\eta| < 2.1$.
        \item Up to 10 hadronic jets clustered with the anti-$k_t$ algorithm ($R=0.4$) having $p_T > 15\,\text{GeV}$ and $|\eta| < 4.0$.
        \item 1 global Missing Transverse Energy (MET) object.
    \end{itemize}
\end{itemize}

The LHC detector geometry defines a right-handed cylindrical coordinate system where the nominal collision point is the origin $(0,0,0)$ and the $z$-axis lies along the proton beam line. The transverse plane $(x,y)$ is perpendicular to the beam line.

The kinematic variables associated with each reconstructed particle slot are defined as:
\begin{enumerate}
    \item \textbf{Transverse Momentum ($p_T$):} The magnitude of momentum projected onto the transverse plane:
    \begin{equation}
        p_T = \sqrt{p_x^2 + p_y^2} \quad [\text{GeV}].
    \end{equation}
    In natural units ($c=1$), $p_T$ is Lorentz-invariant under longitudinal boosts along the $z$-axis.
    \item \textbf{Azimuthal Angle ($\phi$):} The orientation of the transverse momentum vector in the $(x,y)$ plane:
    \begin{equation}
        \phi = \text{atan2}(p_y, p_x) \in [-\pi, +\pi] \quad [\text{rad}].
    \end{equation}
    Because $\phi$ is circular ($-\pi \equiv +\pi$), angular separations must use wrapped differences:
    \begin{equation}
        \Delta\phi(a, b) = \text{atan2}\left(\sin(\phi_a - \phi_b),\, \cos(\phi_a - \phi_b)\right).
    \end{equation}
    \item \textbf{Pseudorapidity ($\eta$):} A spatial coordinate parameterizing polar angle $\theta$ relative to the beam axis:
    \begin{equation}
        \eta = -\ln\left[\tan\left(\frac{\theta}{2}\right)\right] = \frac{1}{2}\ln\left(\frac{|\vec{p}| + p_z}{|\vec{p}| - p_z}\right).
    \end{equation}
    For highly relativistic particles ($m \ll p$), pseudorapidity approximates rapidity $y = \frac{1}{2}\ln\left(\frac{E+p_z}{E-p_z}\right)$, ensuring differences $\Delta\eta$ are invariant under longitudinal Lorentz boosts.
    \item \textbf{Missing Transverse Momentum ($\vec{p}_T^{\,\text{miss}}$):} Defined from the transverse momentum imbalance across all reconstructed objects:
    \begin{equation}
        \vec{p}_T^{\,\text{miss}} = -\sum_{k=1}^{N_{\text{objects}}} \vec{p}_{T,k}, \qquad \text{MET} = |\vec{p}_T^{\,\text{miss}}| = \sqrt{\left(\sum p_{x,k}\right)^2 + \left(\sum p_{y,k}\right)^2}.
    \end{equation}
    MET reflects invisible particles escaping detector hermeticity (neutrinos or hypothetical neutral BSM particles) as well as mismeasurement effects. MET has no meaningful $\eta$ coordinate ($|\eta|_{\text{MET}} \equiv 0$).
\end{enumerate}

\subsection{Fixed-Width Tensor Layout and Padding Semantics}

Each event is encoded as a fixed $(19 \times 4)$ tensor to satisfy fixed-input requirements of machine learning architectures. The 19 slots are allocated into four deterministic object segments:
\begin{equation}
    \text{Slot Layout: } \underbrace{\text{Slot } 0}_{\text{MET } (t=1)} \quad \underbrace{\text{Slots } 1\dots 4}_{\text{Electrons } (t=2)} \quad \underbrace{\text{Slots } 5\dots 8}_{\text{Muons } (t=3)} \quad \underbrace{\text{Slots } 9\dots 18}_{\text{Jets } (t=4)}.
\end{equation}
Within each particle group, objects are sorted in descending order of transverse momentum ($p_{T,0} \ge p_{T,1} \ge \dots$). Unused object slots are padded with type code $t_i = 0$ and all kinematic fields set to $0.0$.

\textbf{Critical Data Engineering Distinction:} Type code $0$ denotes \textbf{structural padding} required by the tensor shape. It is not missing data, a corrupt sensor reading, or a physical particle with zero energy. Our ETL pipeline distinguishes valid structural padding from corrupt records by asserting:
\begin{equation}
    \text{Padding Validity Rule: } (t_i = 0) \implies \left(p_{T,i} = 0.0 \;\land\; \phi_i = 0.0 \;\land\; \eta_i = 0.0\right).
\end{equation}

\subsection{Unsupervised Feature-Space Anomaly Detection Rationale}

In real-time collider triggers, searching for unexpected new physics without specific model assumptions requires \textbf{unsupervised anomaly detection}. Because anomalous events are rare and unpredictable, supervised classifiers cannot be trained against known signal topologies.

This study implements an unsupervised clustering model (\texttt{MiniBatchKMeans}, $K=8$) operating on standardized kinematic features $\mathbf{z} \in \mathbb{R}^{10}$. The atypicality score $s(\mathbf{x})$ of an event $\mathbf{x}$ is defined as the minimum Euclidean distance in standardized feature space to the nearest cluster centroid $\boldsymbol{\mu}_k$:
\begin{equation}
    s(\mathbf{x}) = \min_{k \in \{1,\dots, K\}} \|\mathbf{z}(\mathbf{x}) - \boldsymbol{\mu}_k\|_2 = \min_{k} \sqrt{\sum_{j=1}^{10} \left(\frac{x_j - \bar{x}_j}{\sigma_j} - \mu_{k,j}\right)^2}.
\end{equation}
This distance measures the geometric eccentricity of an event relative to typical Standard Model core distributions. Events with large $s(\mathbf{x})$ reside in sparse topological regions (such as extreme jet multiplicities, highly asymmetric energy balance, or rare high-$H_T$ configurations). This score is an \textbf{exploratory distance metric}, not a calibrated probability of new physics~\cite{adc2021}.

\section{Methodology}

The pipeline executes six sequential stages, each gated on the prior stage's validated output:

\begin{itemize}
    \item \textbf{Stage A: Provenance and Checksum Gate.} Authenticate against Zenodo REST API headers. Verify file size and compute MD5 and SHA-256 digests before committing to \texttt{data/raw/}.
    \item \textbf{Stage B: Full-Corpus Streaming Quality Audit.} Traverse the \texttt{/Particles} tensor in $25{,}000$-event chunks ($1.9\times 10^6$ scalars/chunk). Accumulate exact 64-bit counters for NaN, $\pm\infty$, invalid type codes, negative $p_T$, angular violations, and zero-padding.
    \item \textbf{Stage C: Columnar Feature Extraction \& ETL.} Transform the 3D tensor into a 2D typed table stored as Snappy-compressed Parquet. Derive physical observables ($H_T^{\text{jets}}$, $S_T^{\text{leptons}}$, MET, multiplicity counts, leading-particle momenta) maintaining strict 1:1 row identity.
    \item \textbf{Stage D: Distributed SQL, Window Ranking \& Rollup Cubes.} Apache Spark 3.5.7 executes nine analytical queries, persists a partition-pruned table by $N_{\text{jets}}$, and runs RDD MapReduce aggregations.
    \item \textbf{Stage E: Optional Unsupervised Anomaly Scoring.} A 3-pass streaming \texttt{MiniBatchKMeans} ($K=8$) pipeline standardizes 10 kinematic features and computes nearest-centroid Euclidean distances across all 13.45M events.
    \item \textbf{Stage F: Evidence-Led Visualization Suite.} Generate nine vector figures from freshly produced manifests addressing specific physical and data-quality questions.
\end{itemize}

\section{Implementation, Queries, and Algorithms}

\subsection{Feature Engineering Mathematical Definitions}

Let $i \in \{0, 1, \dots, 18\}$ index the 19 particle slots for event $e$, with transverse momentum $p_{T, i}$, pseudorapidity $\eta_i$, azimuth $\phi_i$, and type code $t_i \in \{0, 1, 2, 3, 4\}$.
\begin{equation}
N_e = \sum_{i=0}^{18} \mathbf{1}(t_i = 2), \quad
N_\mu = \sum_{i=0}^{18} \mathbf{1}(t_i = 3), \quad
N_j = \sum_{i=0}^{18} \mathbf{1}(t_i = 4)
\end{equation}
\begin{equation}
H_T^{\text{jets}} = \sum_{i=0}^{18} p_{T, i} \cdot \mathbf{1}(t_i = 4), \qquad
S_T^{\text{leptons}} = \sum_{i=0}^{18} p_{T, i} \cdot \mathbf{1}(t_i \in \{2, 3\})
\end{equation}
\begin{equation}
p_T^{\text{lead}, e} = \max_{i: t_i=2} (p_{T, i}), \quad
p_T^{\text{lead}, j} = \max_{i: t_i=4} (p_{T, i}), \quad
|\eta|_{\max} = \max_{i: t_i \in \{2, 3, 4\}} |\eta_i|
\end{equation}

\subsection{MapReduce Distributed Key-Value Formulation}

The mapper transforms each event row into key-value pairs keyed by jet multiplicity $N_{\text{jets}}$:
\begin{equation}
\text{Map}(e) \mapsto \left( N_{j, e}, \; \left( 1, \; H_{T, e}^{\text{jets}}, \; \text{MET}_e, \; S_{T, e}^{\text{leptons}} \right) \right)
\end{equation}
The reducer executes associative and commutative elementwise addition over all partition records:
\begin{equation}
\text{Reduce}(k, [v_1, v_2, \dots]) \mapsto \left( \sum 1, \; \sum H_T^{\text{jets}}, \; \sum \text{MET}, \; \sum S_T^{\text{leptons}} \right)
\end{equation}

\subsection{Spark SQL Window Ranking and Rollup Queries}

\begin{verbatim}
-- Query 08: Window Ranking within Jet Slices
WITH ranked_events AS (
  SELECT event_row_id, n_jets, ht_jets, met_pt,
    DENSE_RANK() OVER (PARTITION BY n_jets ORDER BY ht_jets DESC) AS ht_rank_in_slice,
    ROW_NUMBER()  OVER (ORDER BY ht_jets DESC)                    AS global_ht_rank
  FROM events WHERE n_jets > 0
)
SELECT event_row_id, n_jets, ROUND(ht_jets,2), ROUND(met_pt,2),
       ht_rank_in_slice, global_ht_rank
FROM ranked_events WHERE ht_rank_in_slice <= 3
ORDER BY n_jets ASC, ht_rank_in_slice ASC;

-- Query 09: Multidimensional Rollup Cubes
SELECT COALESCE(CAST(n_electrons AS STRING), 'ALL_ELE') AS n_ele,
       COALESCE(CAST(n_muons    AS STRING), 'ALL_MU')  AS n_mu,
       COUNT(*) AS event_count, ROUND(AVG(met_pt),2) AS mean_met,
       ROUND(AVG(ht_jets), 2) AS mean_ht
FROM events GROUP BY n_electrons, n_muons WITH ROLLUP ORDER BY n_ele, n_mu;
\end{verbatim}

\section{Conclusion}

\subsection{Synthesis of Big Data Engineering and Physics Insights}

This case study designed, implemented, and empirically validated an end-to-end Big Data pipeline for the offline processing of LHC 40\,MHz trigger benchmark data. Operating under bounded-memory constraints on a single six-core CPU workstation, the pipeline ingested and analyzed all $13{,}451{,}915$ collision events ($1.022\times 10^9$ tensor scalars) with strict row-count conservation and zero data subsampling.

The central research question posed in Section~\ref{sec:problem_statement} --- whether a memory-bounded pipeline can audit raw collider tensors, derive interpretable physics observables, perform distributed SQL and MapReduce aggregations, and rank topological outliers using unsupervised models --- is affirmed across all experimental milestones:
\begin{enumerate}
    \item \textbf{Data Integrity and Schema Provenance:} Provenance was cryptographically anchored to Zenodo Record 5046428 ($646.4\,\text{MB}$, MD5 \texttt{08cb4801229f9d480567f8d3f5cac134}). The chunked audit validated $100\%$ of tensor coordinates against non-finiteness, invalid particle type codes, unphysical negative $p_T$, and azimuthal overflow ($|\phi| > \pi$), confirming zero data corruption across the corpus.
    \item \textbf{Columnar Storage Efficiency:} Bounded-memory ETL transformed 3D HDF5 tensors into Snappy-compressed Apache Parquet ($539$ row groups), achieving a $1.39\times$ on-disk compression ratio against uncompressed payloads while enabling columnar projection and partition pruning.
    \item \textbf{Scalable Analytics and Ecosystem Interoperability:} Nine Spark SQL queries and Spark RDD \texttt{map/reduceByKey} pipelines demonstrated high-throughput distributed aggregations. Standardized dataflow artifacts for Apache Pig Latin local mode, Apache Hive DDL, and Hadoop Streaming established multi-engine interoperability across the Hadoop/Spark ecosystem.
    \item \textbf{Unsupervised Anomaly Characterization:} An online, multi-pass \texttt{MiniBatchKMeans} ($K=8$) architecture mapped all $13.45\times 10^6$ events into standardized feature space, providing a calibration-free geometric ranking of rare Standard Model topologies.
\end{enumerate}

\subsection{Summary of Empirical Physics Findings}

\begin{itemize}
    \item \textbf{Trigger Pre-selection Signatures:} The single-lepton trigger pre-selection ($p_T > 23\,\text{GeV}$) creates sharp turn-on thresholds in electron and muon spectra. The underlying Monte Carlo cocktail ($59.2\%$ $W \to \ell\nu$, $33.8\%$ QCD multijet, $6.7\%$ $Z \to \ell\ell$, $0.3\%$ $t\bar{t}$) directly governs the observed bimodal $H_T$ and $S_T^{\text{lep}}$ energy distributions.
    \item \textbf{Jet Multiplicity Hierarchy:} Purely leptonic events ($N_j = 0$) constitute $37.8\%$ of the dataset, while $86.0\%$ have $N_j \le 2$. The extreme multi-jet tail ($N_j \ge 5$, $0.77\%$ of events) drives total hadronic activity ($H_T$) and exhibits heavy-tailed non-Gaussian energy scaling.
    \item \textbf{Kinematic Decoupling:} A Pearson correlation $r = 0.13$ between MET and $H_T$ confirms that missing momentum (neutrino recoil / detector imbalance) and scalar hadronic activity provide independent, orthogonal discriminating dimensions for event filtering.
    \item \textbf{Topological Complexity vs.\ Anomaly Score:} Median anomaly distance scales strictly monotonically from $s_{\text{med}} = 1.15$ at $N_j = 0$ to $s_{\text{med}} = 7.12$ at $N_j = 10$. Standardized feature scaling ensures that outlier scores reflect genuine topological rarity in multi-dimensional space rather than raw energy magnitude artefacts.
\end{itemize}

\subsection{Limitations and Defensible Scope Boundaries}

In alignment with rigorous scientific integrity principles, the following explicit boundaries define this study:
\begin{itemize}
    \item \textbf{Single-Host Docker Execution:} All Spark computations executed in \texttt{local[6]} multithreaded mode on a single physical host. No distributed network cluster scaling or true HDFS throughput numbers are claimed.
    \item \textbf{Absence of Per-Event Ground Truth:} The training dataset is a pure Standard Model simulation mixture without per-event BSM signal labels. Consequently, supervised signal efficiency, background rejection curves, precision-recall, and ROC-AUC cannot be derived from this record alone.
    \item \textbf{Model-Relative Anomaly Metrics:} Outlier scores represent empirical Euclidean distances to KMeans centroids in standardized feature space; they are not calibrated $p$-values or physical discovery significances.
    \item \textbf{Tool Execution Modes:} Spark SQL and RDD operations ran natively over the full dataset. Apache Pig 0.17 ran in \texttt{-x local} mode, while Hive DDL and Hadoop Streaming scripts were provided and structurally verified as catalog/deployment artifacts.
\end{itemize}

\subsection{Future Research Directions}

Promising technical extensions to this pipeline include:
\begin{enumerate}
    \item Stratified intra-multiplicity anomaly scoring (fitting separate models per $N_j$ bin) to isolate fine-grained sub-structure anomalies from dominant multiplicity scaling.
    \item Deployment of the Hadoop Streaming and Hive scripts onto a distributed multi-node YARN/HDFS cluster to quantify scale-out speedup and I/O saturation.
    \item Ingestion of the official ADC2021 black-box evaluation mixtures containing injected exotic resonance signatures ($A \to 4\ell$, $h^0 \to \tau\tau$, $W' \to \text{jet}+\ell$, $LQ \to b\tau$) to benchmark unsupervised signal discovery curves and false-positive rejection rates.
    \item Integration of exact t-digest or KLL sketch algorithms to eliminate approximate quantile sampling variance in ultra-high percentile calculations ($P_{99.99}$).
\end{enumerate}

All code, SQL queries, MapReduce mappers/reducers, ETL routines, ML scoring scripts, and vector figures are containerized and fully reproducible via the project Makefile and Docker Compose configuration.
